# Hardening

This page lists what the security modules change, which part of the CIS Benchmarks for Debian, Ubuntu and Red Hat
Enterprise Linux each one covers, and where lss deliberately does something else. Every value below can be checked on
a server with `lss verify`; the `lynis` module gives a second opinion with `lss audit`.

The profile `minimal-secure` installs everything in this list except the modules marked opt-in. On fresh Debian 12
and 13 cloud images it reaches a Lynis hardening index of 87 and 85, on the Ubuntu 24.04 GitHub runner (which brings
Docker, databases and its own sudo rules) 78. CI checks that it stays at 82 on Debian and 75 on the runner.

## What the modules do

| Module             | Changes                                                                                                                                          | CIS area                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------- |
| `admin-user`       | One administrator with SSH keys only (RSA at least 3072 bits), sudo through the sudo or wheel group (with a pseudo terminal, a 5-minute timestamp and its own log file; sudo-rs logs to the journal), a generated password for the console | User accounts, sudo                   |
| `ssh-hardening`    | No root login, no passwords, public keys only, `AllowGroups`, 3 tries, 30 s login grace, idle sessions closed after 15 minutes, no agent, X11 or tunnel forwarding, verbose logging, `sshd_config` readable by root only, a login banner (also in `/etc/issue` and `/etc/issue.net`), modern key exchange (ML-KEM and sntrup761 hybrids first), AEAD ciphers first with AES-CTR as fallback, encrypt-then-MAC MACs only, DH moduli of 3072 bits and more | SSH server                            |
| `ssh-2fa` (opt-in) | A TOTP code in addition to the key, per user                                                                                                    | SSH server, authentication            |
| `firewall`         | ufw or firewalld, everything inbound closed except SSH and the ports of installed modules; a rollback timer switches it off again if SSH cannot be confirmed | Host-based firewall                   |
| `fail2ban`         | Bans after 5 failures in 10 minutes, ban time grows from 1 hour to 1 week, a recidive jail for repeat offenders, bans through nftables          | (not in CIS; defence in depth)        |
| `crowdsec` (opt-in, instead of fail2ban) | Behaviour detection with shared block lists, bouncer on nftables                                                          | (not in CIS; defence in depth)        |
| `kernel-hardening` | ASLR, restricted kernel pointers and dmesg, ptrace scope 1, unprivileged BPF off, SysRq off, protected links, FIFOs and regular files, no core dumps of setuid programs, reverse path filter, no ICMP or IPv6 redirects, no source routing, SYN cookies, martians logged; unused file systems and protocols blocked (cramfs, freevxfs, hfs, jffs2, udf, dccp, sctp, rds, tipc, FireWire, Thunderbolt, Bluetooth), USB storage blocked; core dumps off | Kernel parameters, file system modules, network parameters |
| `mac`              | AppArmor (Debian, Ubuntu) or SELinux (Rocky, AlmaLinux) enabled and enforcing                                                                    | Mandatory access control              |
| `auditd`           | Audit rules for identity files, sudoers, logins, time changes, network configuration, permission changes, failed file access, mounts, deletions, kernel modules, sudo use, cron and the MAC policy; `audit=1` on the kernel command line; process accounting (acct/psacct) | System auditing                       |
| `auto-updates`     | Security updates every day (unattended-upgrades or dnf-automatic), services restarted after updates (needrestart on Debian and Ubuntu), an automatic reboot at 04:00 when an update needs one | Software updates                      |
| `password-policy`  | At least 14 characters with pwquality, account locked for 15 minutes after 5 failures (faillock), umask 027, idle shells log out after 15 minutes, costlier password hashes (100,000 SHA-512 rounds, yescrypt cost 7), a private TMPDIR per session (libpam-tmpdir, Debian and Ubuntu) | Password policy, PAM, shell timeout   |
| `aide`             | File integrity database, checked every day; debsums for the package checksums on Debian and Ubuntu                                             | File integrity                        |
| `rkhunter`         | Rootkit scan every day; like the AIDE, ClamAV and Lynis runs it is confined by systemd (read-only system, no new privileges, writes only to its own state and logs) | (not in CIS)                          |
| `clamav` (opt-in)  | Virus signatures updated several times a day, daily low-priority scan of writable directories                                                    | (not in CIS)                          |
| `lynis`            | Weekly audit with the hardening index kept as history; `lss audit` fails below a minimum you set                                                | (audit tool)                          |
| `usbguard` (opt-in)| Only the USB devices present at installation are allowed                                                                                         | Removable media                       |
| `system`           | System crontab and cron directories readable by root only (600 and 700)                                                                         | Job schedulers                        |
| `logging`          | Persistent journal with size and age limits, optional forwarding to a syslog server over TLS                                                     | Logging                               |
| `time`             | chrony with NTS-authenticated servers, no NTP port open                                                                                          | Time synchronisation                  |
| `guard`            | Runs `lss verify` every day, repairs modules that failed or were changed outside lss, reports failed units, full disks, pending security updates, vulnerable packages, a needed reboot, a low Lynis index, AIDE/rkhunter/ClamAV findings and failed SSH logins; notes logins and bans | (operations)                          |
| `nginx`, `apache`, `caddy` | One web server owns ports 80 and 443: HTTPS only with TLS 1.2 and 1.3 (Mozilla intermediate, ECDHE only), HSTS for two years, `nosniff`, `SAMEORIGIN` framing, a strict referrer and permissions policy, no version banner; unknown host names get no answer; dot files are never served; admin interfaces only on 127.0.0.1:8090 unless `LSS_<SERVER>_ADMIN_PUBLIC=true` (then TLS and a password); the service runs in a systemd sandbox; fail2ban or CrowdSec read its logs | CIS Apache/nginx benchmarks, Mozilla TLS guidelines, OWASP Secure Headers |
| `tls`              | Certificates from Let's Encrypt (or any ACME server) with ECDSA keys, renewed by a timer; private keys readable by root and the web server group only; OCSP stapling where the certificate names a responder; guard warns 14 days before a certificate expires | Mozilla TLS guidelines |
| `php`              | Own pool user `lss-php`, socket `0660 root:lss-web` only, the distribution's `www` pool off, `expose_php` and `display_errors` off, `allow_url_include` off, `cgi.fix_pathinfo=0`, secure, HTTP-only and SameSite session cookies with strict mode, a private session directory, `exec`, `system`, `proc_open` and similar functions disabled for the web pool, only `.php` executed, systemd sandbox (read-only system except `/var/lib/php` and `LSS_PHP_WRITABLE_PATHS`) | OWASP PHP Configuration Cheat Sheet |
| `dotnet`           | `DOTNET_CLI_TELEMETRY_OPTOUT=1` for every login | (privacy) |
| `phpmyadmin`       | Checksum-verified release without the setup wizard; configuration readable by root and PHP-FPM only, with a generated cookie secret; only the local database server, no root and no empty-password logins; no version check and no error reports; only on the admin port | (operations) |
| `adminer`          | Checksum-verified release; a login plugin allows only the configured local servers and drivers; only on the admin port | (operations) |
| `pgadmin`          | Pinned, checksum-verified wheels in an isolated environment; own system user; systemd sandbox without capabilities; bound to 127.0.0.1; no upgrade check, no psql tool, no browsing of binary paths; secure cookies when the admin port is public | (operations) |
| `modsecurity`      | Requests filtered by ModSecurity with the OWASP Core Rule Set (anomaly scoring, paranoia level 1 by default) and blocked with 403; matches go to an audit log without request bodies | OWASP CRS |
| `mariadb`          | Bound to 127.0.0.1, `local-infile=0`, root only through the Unix socket, no anonymous accounts and no test database, one least-privilege user per application, systemd sandbox | CIS MariaDB |
| `mysql`            | Bound to 127.0.0.1 (the X protocol too), `local-infile=0`, root through `auth_socket` (RHEL: a generated password in `/root/.my.cnf` 0600); root never exists without a password; systemd sandbox | CIS MySQL |
| `postgresql`       | localhost, `scram-sha-256`, TLS 1.2 or later, peer login only for `postgres`, each role reaches only its own database, PUBLIC loses CONNECT and CREATE, systemd sandbox | CIS PostgreSQL |
| `redis`, `valkey`  | localhost, ACL password stored as SHA-256, `FLUSHALL`, `CONFIG`, `DEBUG`, `MODULE` and similar commands blocked, systemd sandbox | (vendor guide) |
| `mongodb`          | Authorization from the first start, bound to 127.0.0.1, no Unix socket, server-side JavaScript off, mongosh telemetry off, least-privilege application users, systemd sandbox | CIS MongoDB |
| `docker`           | Docker CE from Docker's repository with pinned keys (`docker.io` where Docker builds nothing); `daemon.json`: no traffic between containers on the default bridge (`icc` off), published ports on 127.0.0.1 unless a container names an address, `live-restore`, `userland-proxy` off, `no-new-privileges`, the local log driver with size limits, `nofile` limits, user namespace remapping, SELinux labels on the RHEL family, the default seccomp profile; the API only on its Unix socket (mode 660, root); published ports behind the container firewall | CIS Docker, sections 2 (daemon) and 3 (socket) |
| `podman`           | Podman from the distribution, no daemon; process limit, log size limit and `nofile` limits for every container; seccomp checked, SELinux labels checked when SELinux enforces; published ports behind the container firewall | CIS Docker, sections 2 and 5, applied to Podman |
| Containers of lss (`lib/container.sh`) | Image pinned by digest, `no-new-privileges`, all capabilities dropped (the dangerous ones never added), read-only root with a small `/tmp`, memory and process limits, never the host's network, PID or IPC namespace, published ports with an address, never the engine socket (Portainer is the one exception) or system paths, also through symbolic links; Compose files are checked against the same rules | CIS Docker, section 5 (container runtime) |
| Container firewall | Published container ports (Docker, Podman, Kubernetes NodePorts and hostPorts) are forwarded past the INPUT rules of ufw and firewalld; an own nftables chain lets a redirected connection through only when a module opened that port with the same scope, and drops new connections straight to container addresses | CIS Docker, section 5 (published ports); host firewall |
| `portainer`        | Pinned image digest, on 127.0.0.1:9443 or the WireGuard network only, the admin password from the lss secrets (a container sees only its own directory below `/etc/lss/containers`), data on a named volume, read-only root, no capabilities; optionally below `/portainer/` on the admin port | (operations; deliberate socket exception, see below) |
| `k3s`              | Pinned, checksum-verified binary; secrets encrypted at rest, kubeconfig 0600, `protect-kernel-defaults` with the kernel values the kubelet expects, Pod Security admission (`restricted` everywhere except `kube-system`), an audit log (metadata, 30 days), idle streaming connections closed after 5 minutes, finished pods collected; k3s-selinux on the RHEL family; the API on 127.0.0.1 unless opened; pod traffic to the host only from the pod network on its bridge | CIS Kubernetes Benchmark as applied by the k3s CIS Hardening Guide (control plane, kubelet, Pod Security) |
| `guard` with a container engine | Trivy scans every image daily and reports HIGH and CRITICAL vulnerabilities per image | CIS Docker, section 4 (images) |
| `haproxy`          | Statistics only on 127.0.0.1, admin socket readable by root only, chroot, systemd sandbox, ports in the firewall only for services that are not `local` | (operations) |
| `mail-relay`       | Postfix on 127.0.0.1 and ::1 only, no relaying for anyone else; TLS to the smarthost with its certificate checked against the system CAs (DANE or opportunistic TLS without one), the smarthost password in a 0600 table; no delivery to programs, files or `~/.forward`; no chroot, a systemd sandbox instead | (operations) |
| `mailserver`       | Postfix: no open relay, submission on 587 and 465 only with TLS 1.2 or later and a login, the sender address tied to the login in the envelope and, through an Rspamd prefilter, in the From header, login attempts rate-limited, no VRFY, strict HELO and recipient checks; Dovecot: IMAPS only (plain IMAP on 127.0.0.1 for webmail), SHA-512-crypt passwords in a 0640 file, mailboxes in `/var/vmail` (0700, own user); Rspamd: rejects spam, signs with DKIM (RSA 2048, keys 0640) only for the domain of the login or for mail of the server itself, checks SPF, DKIM and DMARC, its web interface off; every service in a systemd sandbox | (operations; Mozilla TLS guidelines) |
| `webmail`          | Checksum-verified Roundcube without the installer, configuration readable by root and PHP-FPM only, a generated DES key, IMAP and SMTP on 127.0.0.1 only, strict SameSite session cookies bound to the client address, HTTPS only through the web server | OWASP Session Management |

## Deliberate deviations

These settings differ from a strict reading of the benchmarks. Each one has a setting to change it.

| Setting                                             | lss default                         | Reason                                                                                                                                       | Change with                                       |
| --------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| IPv6 router advertisements (`accept_ra`)            | accepted                            | Many hosters configure IPv6 through router advertisements; turning them off removes the server's IPv6 address.                               | `LSS_KERNEL_HARDENING_IPV6_ROUTER_ADVERTISEMENTS=false` |
| SSH port forwarding                                 | `local` (only `ssh -L`)             | Admin interfaces that listen on localhost (databases, dashboards) are reached through an SSH tunnel instead of an open port.                 | `LSS_SSH_HARDENING_TCP_FORWARDING=no`             |
| Audit rules immutable (`-e 2`)                      | off                                 | With immutable rules, every rule change by a later module needs a reboot. Turn it on once the server is complete.                            | `LSS_AUDITD_IMMUTABLE=true`                       |
| Two-factor login                                    | opt-in                              | Each user has to enrol an authenticator app first; enforcing it before that locks them out.                                                  | install `ssh-2fa`, then `LSS_SSH_2FA_ENFORCE=true`|
| Malware scanner                                     | opt-in                              | ClamAV needs about 1.6 GB of RAM while it scans, more than small servers have.                                                           | install `clamav`                                  |
| USB device allow-list                               | opt-in                              | Virtual servers have no USB ports; on hardware it blocks keyboards plugged in later.                                                         | install `usbguard`                                |
| Password expiry                                     | 365 days                            | NIST SP 800-63B advises against forced rotation; logins use SSH keys, so the password is only for the console and sudo.                      | `LSS_PASSWORD_POLICY_MAX_DAYS`                    |
| Automatic reboot                                    | on, 04:00                           | Kernel and libc fixes only take effect after a reboot; a server that never reboots stays vulnerable.                                         | `LSS_AUTO_UPDATES_REBOOT=false`                   |
| Docker restart policy                               | `unless-stopped` for containers of lss | CIS Docker suggests `on-failure` with at most 5 restarts; a management container that stops after five crashes leaves the server unmanaged.               | –            |
| Engine socket in Portainer                          | mounted                             | CIS Docker forbids mounting it into containers; Portainer cannot manage the engine without it. It is the only container that gets it, it runs on 127.0.0.1 or the WireGuard network only, and it runs in the host's user namespace and, on the RHEL family, without SELinux separation to reach the socket. | do not install `portainer` |
| Docker user namespace remapping                     | on                                  | Images that expect to own host paths as root need it off.                                                                                     | `LSS_DOCKER_USERNS_REMAP=false` |
| Docker and k3s together                             | not possible                        | Each brings its own containerd and claims the forwarding rules; `profiles/all.conf` has Docker, `profiles/k8s-node.conf` has k3s.            | –            |
| Kubernetes API                                      | 127.0.0.1                           | kubectl through an SSH tunnel; a cluster with more nodes or remote tooling needs `vpn` or `public`.                                           | `LSS_K3S_API_ACCESS` |
| Traefik in k3s                                      | on                                  | The bundled ingress controller serves ports 80 and 443 for the cluster; without it you bring your own.                                        | `LSS_K3S_TRAEFIK=false` |

## What lss does not do

Some benchmark items cannot be applied safely to a running server, so lss reports them instead of changing them:

- **Separate partitions** for `/tmp`, `/var`, `/var/log`, `/var/log/audit` and `/home`, and mount options such as
  `noexec` on them. They are decided when the disk is partitioned. Set them up in the installer or the image of your
  hoster; Lynis lists the missing ones.
- **A boot loader password.** It stops an unattended reboot of a remote server at the boot menu.
- **Disk encryption.** Like partitions, it is set up when the system is installed.
- **Docker's auditd rules** (CIS Docker, section 1). The `auditd` module watches identity files, sudo and the
  kernel; rules for every Docker file are not part of it yet.
- **Docker content trust and image signatures** (CIS Docker, section 4). lss pins its own images by digest; images you run
  yourself are your choice. The daily Trivy scan reports their known vulnerabilities.
- **Kubernetes workloads.** k3s gets a hardened control plane and Pod Security admission; network policies, RBAC for
  your users and the images of your pods are part of what you deploy.
- **Removing packages of the distribution** that a benchmark calls unnecessary. lss installs only what its modules
  need and leaves the rest to the image you started from.
